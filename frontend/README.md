# Dineary 프로토타입

별도 패키지 설치나 빌드 없이 실행하는 HTML·CSS·JavaScript 프로토타입입니다.

프로젝트 루트에서 실행:

```sh
python3 -m http.server 5173 --bind 127.0.0.1 --directory frontend
```

브라우저에서 http://127.0.0.1:5173 접속. `frontend/index.html`을 직접 열어도 화면을 볼 수 있지만, 데이터 저장은 위 서버 실행 방식을 권장합니다.

- 음식점·메뉴·지역 검색, 지역·음식 종류·혼밥 필터, 평점·가격·리뷰 수 정렬
- 닉네임·이메일·비밀번호로 회원가입, 로그인·로그아웃, 이메일 중복·비밀번호 확인 검사
- 로그인 전 음식점 탐색 가능, 저장·리뷰·예약 및 개인 기록은 로그인 후 이용
- 음식점 상세 정보·메뉴·샘플 지도 표시
- 가게 저장·해제 및 저장 목록
- 리뷰 작성·삭제, 평점·리뷰 수 반영
- 예약 체험·중복 방지·취소 및 나의 기록
- 모바일 반응형, 키보드 탐색, Escape로 상세 닫기

음식점 6곳과 리뷰·이미지·지도는 가상의 샘플입니다. 리뷰·저장·예약은 `localStorage`의 `dineary-prototype-v1:user:<사용자 ID>` 키에 계정별로 저장됩니다. 예약은 실제로 전달되지 않으며 휴무일·잔여 좌석과 연동되지 않습니다. 화면의 기본 리뷰 수는 예시 집계이며 리뷰 전체 목록을 의미하지 않습니다.

회원가입하면 자동 로그인됩니다. 로그인 상태는 `sessionStorage`에 보관하여 같은 탭에서 새로고침해도 유지하며, 로그아웃 후에도 계정과 기록은 남습니다. 계정은 `localStorage`의 `dineary-accounts-v1`에 저장하고 비밀번호는 임의 salt를 사용하는 PBKDF2-SHA-256 결과로 저장합니다. 브라우저만으로 구현한 체험 기능이므로 실제 인증·접근 통제 기능을 제공하지 않습니다. 실제 사용하는 비밀번호는 입력하지 마세요. 이메일 인증·비밀번호 재설정은 포함하지 않습니다.

이전 비회원 기록 키 `dineary-prototype-v1`은 삭제하지 않고 보존하며, 새 계정에 자동 연결하지 않습니다. 기존 데이터를 특정 사용자에게 임의로 배정하지 않기 위한 처리입니다.

Spring Boot·DB 연동, 지도 API, 사장님·관리자 화면, 개인화 추천은 포함하지 않습니다. `auth.js`의 인증 함수와 `app.js`의 샘플 데이터·저장 함수를 서버 API 호출로 교체하며 확장할 수 있습니다.

- `index.html`: 화면 골격
- `styles.css`: 디자인 및 반응형 레이아웃
- `auth.js`: 회원가입·로그인·로그아웃 및 체험용 계정 저장
- `app.js`: 샘플 데이터, 화면 렌더링, 상호작용과 브라우저 저장
